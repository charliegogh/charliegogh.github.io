# Git 协同与提交规范

为提升团队协作效率、降低冲突风险、支持自动化流程，x-cli 工程默认集成 Git 提交校验机制，要求所有提交信息遵循统一格式。

---

## 📁 分支命名规范

| 分支类型    | 命名示例                  | 说明                     |
|---------|-----------------------|------------------------|
| 主分支     | `master`              | 正式发布版本                 |
| xtest分支 | `xtest`               | 测试发布版本                 |
| 开发分支    | `develop`             | 日常集成开发                 |
| 功能分支    | `feature/xxx-module`  | 新功能开发，基于 `develop` 创建  |
| 修复分支    | `fix/xxx-bug`         | Bug 修复，基于 `develop` 创建 |
| 发布分支    | `release/1.0.0`       | 准备上线版本，进入灰度测试阶段        |
---

## ✅ 提交规范（Commit Message）

### 格式要求：

```bash
<type>(scope): 描述内容
```

### 常见类型（type）：

| 类型         | 说明              |
| ---------- | --------------- |
| `feat`     | 新功能             |
| `fix`      | Bug 修复          |
| `docs`     | 文档变更            |
| `style`    | 样式调整，不影响功能      |
| `refactor` | 代码重构            |
| `test`     | 测试相关代码          |
| `chore`    | 构建脚本/依赖调整等非功能更改 |

### 提交示例：

```bash
feat: 新增登录跳转逻辑支持
fix: 修复导出数据时字段缺失问题
docs: 增加本地启动文档说明
```

## 🔒 x-cli 中的提交校验机制说明

x-cli 工程内置 Git 提交规范约束，默认集成以下工具：

| 工具            | 功能                   |
| ------------- | -------------------- |
| `husky`       | Git 钩子，提交前自动触发校验     |
| `commitlint`  | 校验提交信息是否符合规范格式       |
| `lint-staged` | 提交前自动格式化代码（如 ESLint） |

当你执行 `git commit` 时，会自动校验提交信息格式是否符合规范：

```bash
git commit -m "修改了bug"
```

⚠️ 将会被拦截，提示格式不规范：

```
⛔️ [commitlint] Invalid commit message
  ❌ type may not be empty
  ❌ subject may not be empty
```


### 🛠 常见处理说明

| 场景           | 建议处理方式                            |
| ------------ | --------------------------------- |
| 想跳过校验（不推荐）   | 可使用 `git commit --no-verify`（调试用） |
| 提交前想自动修复格式错误 | 已内置 `lint-staged`，保存时会自动执行 ESLint |

## 🔁 合并建议流程（PR）

* 所有代码应通过 MR/PR 合并，避免直接推送至 `main`；
* 功能完成后合并至 `develop`；
* 发版由负责人处理 `release/*`、`hotfix/*` 分支合并流程；
* 主分支禁止直接提交。
